What this validator checks

Beyond simply parsing your input, this tool reports the exact line and column where parsing failed — rather than a raw character offset — so you can jump straight to the problem in your editor instead of counting characters by hand. Common failures it catches: trailing commas, unquoted object keys, single quotes instead of double quotes, and missing closing brackets.

Why does formatting a large payload sometimes take a moment?

For inputs over roughly 500KB, parsing is handed off to a Web Worker — a separate background thread — specifically so the browser tab's scrolling and typing stay responsive while a large document is validated. Smaller inputs are parsed instantly on the main thread since the delay would be imperceptible either way.

Does "sort keys" change the meaning of my JSON?

No — object key order is not semantically meaningful in JSON itself (unlike array order, which always matters). Sorting keys only affects readability and diff-friendliness when comparing two versions of a config file; it has no effect on how any JSON parser interprets the data.

Is minified JSON actually smaller over the network?

Minification removes whitespace, which helps before gzip/Brotli compression is applied — but most production servers already compress JSON responses, and compression closes much of that gap on its own. Minifying is most useful for reducing parse time and memory on the receiving end, not primarily for transfer size on a server that already compresses responses.
