# Teacher daily diary and student profile — 19 November 2026

## Teacher portal
All saved subjects for the assigned class appear as individual homework cards. Fill instructions or title, optionally choose a due date, then post all filled subjects. Blank subjects are excluded; already-posted subjects remain visible. The new backend writes a batch under a script lock and verifies the rows, with a request ID and payload hash for safe retries. Existing class-wide teacher sessions may use the old single-entry API in sequence only after an explicit unsupported-action response. Legacy uncertain writes require saved-history review; section-specific batch posting requires the new backend. Actual authenticated Apps Script testing is still required.

Student photos and identity fields are displayed when available; fatherGuardian is the canonical father/guardian field, also used by the monthly register. Student record opens the education, admission and contact details with attendance history. Editable fields are fatherGuardian, contact, whatsapp, address, guardianName, guardianRelation, guardianCell and teacherRemarks. Official identity, admission, enrollment, credentials and class remain admin controlled. Changes are checked against expected field values, teacher assignment and subscription; attempt and verified audits are recorded. Personal credentials, CNIC and income are redacted from teacher list/get responses in the updated backend. Edits are verified by reading back requested fields; interrupted multiple-cell edits require a fresh read before retry.

## Rollout
Deploy the complete backend-api/code.gs in the existing Apps Script deployment, not a new project or setup. Keep all other script files and Script Properties. Test a six-subject diary using an approved test teacher, same-batch retry, another class rejection, authorized profile save and denied identity edit, and section-specific student visibility. Backend source in GitHub does not by itself update the live Apps Script service. No actual student records were modified by development. 22 mock backend and 12 mock UI/API checks passed before the final sheet growth safeguard. No real classroom session or Android rendering was tested.
